# Nocturne runs on Windows through a thin portability layer; Metal stays the Apple backend

Nocturne gets a Windows port ([#35](https://github.com/Azylume/nocturne/issues/35)) that does everything the Mac mini does: every effect, clips, fullscreen outputs, recording, return video and audio, audio input, Node Sync, discovery, the desk, the supervisor and the JUCE UI. The engine stays one C++20 code base. Platform code sits behind small interfaces whose implementation is picked at compile time, so macOS keeps its current code paths and its performance, and a later Linux build can reuse the non-Apple side.

- **GPU: our own thin interface, backend chosen at compile time.** Metal on Apple, Vulkan 1.3 elsewhere. There are no per-draw virtual calls: one backend is compiled in, so the render thread pays nothing for the choice. MoltenVK (a second translation layer on the Mac, and the Mac's performance is the one ADR 0008 measures) and CUDA (one vendor) were rejected.
- **Shaders: one source, GLSL.** Every shader, built-in or user, is GLSL; effects are ISF `.fs` files and stay plug and play from a folder ([#34](https://github.com/Azylume/nocturne/issues/34)). glslang compiles to SPIR-V; Vulkan uses SPIR-V directly and the Mac converts it to MSL with SPIRV-Cross. The chain planner fuses in GLSL, so ADR 0009 holds on both backends: one compile per chain, on the compiler thread, never on the render thread.
- **Video: FFmpeg off Apple.** An LGPL build of the FFmpeg libraries (through vcpkg) decodes with NVDEC, demuxes and muxes HAP into the existing snappy and BC upload path, records HEVC with NVENC plus ProRes (`prores_ks`) and AAC, encodes return video as H.264 and carries Opus through libopus. The Apple path (VideoToolbox, AVFoundation) is unchanged.
- **Network: plain sockets off Apple.** WebSocket (RFC 6455) and the UDP clock on Winsock/POSIX sockets, the Windows DNS-SD API (`DnsServiceRegister`, `DnsServiceBrowse`) for discovery, WinHTTP for uploads, `GetAdaptersAddresses` for interfaces. The Mac keeps Network.framework. The trust model in `SECURITY.md` (pairing token, `Origin` refusal, pre-pairing limits) is the same on both.
- **Previews: shared memory and a CPU readback** from engine to UI on Windows; IOSurface stays on the Mac. Zero-copy comes later, and only if measured.
- **Audio: WASAPI capture and process loopback** (Windows 10 2004 and later). pocketfft replaces vDSP off Apple; the UI plays return audio through JUCE.
- **Threads and timing: a thin queue interface**, GCD on Apple and `std::thread` elsewhere. On Windows the render and present threads use MMCSS and `timeBeginPeriod(1)`, time comes from QPC (`steady_clock`), and vsync from the Vulkan FIFO present and DWM. ADR 0003 holds: one present thread per output.
- **Displays: a borderless Win32 window per monitor**, found with `EnumDisplayMonitors` and re-found on `WM_DISPLAYCHANGE`, plus windowed and virtual displays and the safe-mode window.
- **Process and trust:** `CreateProcess` with a job object and the same heartbeat pipe as on the Mac; user data in `%LOCALAPPDATA%\Nocturne`; the Tailscale key in Credential Manager; BCrypt for hashing, HMAC and random bytes. Bundle update is off on Windows until signed builds exist.
- **Thermal: WMI and the Windows throttling signal**, "unknown" otherwise. NVML is not used: it is closed native code (ADR 0014).
- **Text: DirectWrite on Windows**; CoreText stays on the Mac.
- **Tests: one harness for both.** It reads back through the GPU interface, writes PNG through stb on every platform, and checks the same goldens with the same tolerance. A file in `tests/golden/vulkan/` exists only where Vulkan output really differs, and each one is opened and listed in its PR.
- **Toolchain: clang-cl with the MSVC STL, Ninja and a vcpkg manifest** on Windows. The Mac build stays as it is, Universal by default.
- **CI:** a `windows` job on `windows-latest` builds, runs the tests that need no GPU and keeps an installer artifact. The GPU suite runs on a Windows machine with a GPU and its output goes in the PR.
- **Installer: Inno Setup.** Program Files, a Start menu entry, the VC++ runtime and FFmpeg DLLs, optional autostart through Task Scheduler; uninstall keeps `%LOCALAPPDATA%\Nocturne`. Unsigned for now, like the Mac preview (ADR 0015).

New dependencies, all AGPL-compatible (ADR 0012): FFmpeg (LGPL build) with libopus, pocketfft, the Vulkan headers and loader, and Inno Setup as a build tool only.

- **Amends ADR 0001.** The engine is still C++20 and still renders with Metal on Apple through metal-cpp; Metal is now one backend of the GPU interface instead of the only renderer, and Apple-only APIs stay in their Objective-C++ files behind the engine, media and output boundaries. The reason 0001 rejected OpenGL (deprecated on macOS, single-threaded presentation) still holds, and it is why the second backend is Vulkan.

- **Considered:** MoltenVK with Vulkan everywhere (rejected: it adds a layer and a risk on the machine whose budget decides, and it gives up the Metal code that already meets it); a per-platform fork of the engine (rejected: every feature would land twice); a runtime-selectable GPU backend (rejected: a virtual call per draw for a choice that never changes while a show runs).

The cost: every built-in Metal shader is rewritten once as GLSL and goes through a cross-compiler on the Mac, and each platform API has two implementations to keep in step. A Mac golden that changes, or a generated shader that is measurably slower than the hand-written one, stops the port of that piece.
